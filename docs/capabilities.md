# Scenario capability matrix

“Not measured” is not zero. A supported input shape, user observation, historical diagnostic and qualified accuracy result are different kinds of evidence. PARSeq is a crop recognizer; it does not perform full-frame detection or promise generic selective reading.

| Scenario | PARSeq Base / Tiny / Fast Tiny evidence | WATERec / Florence context |
|---|---|---|
| Familiar upright alphanumeric plates | Base: historical 2,415/2,693. Fast Tiny: verified 203/256 mixed timing subset, not a full-cohort qualification. Standard Tiny full ALPR result is NM. | WATE RS512: 2,475/2,693 and separate unseen 880/984. Florence: 2,381/2,693 and 857/984. These are separate trained checkpoints and cohorts. |
| Unseen countries / fonts | Legacy PARSeq: 327/443 international crops; the US subset 164/222 exceeded WATE's 151/222. This does not establish all countries, scripts or pretraining novelty. | WATE's 332/443 and Florence's 191/443 on that snapshot are contextual, not universal rankings. |
| Two-line crops / reading order | Whole crop is resized to configured fixed H×W. No isolated, qualified two-line score is supplied for the supported PARSeq presets. A 2D ViT encoder alone is not a proof of ordering accuracy. | WATE keeps aspect-aware spatial patches, but architecture alone is not a two-line benchmark. Florence layout capability still needs the actual requested test. |
| Native 90° / 180° / 270° reading | Historical PARSeq: 31/152/226 of788; Fast Tiny: 6/0/182. Upright on the same historical set: 598/579. No correction wrapper. | These are not current Florence-engine comparisons. A separately qualified WATE orientation pipeline is a pipeline feature, not reader invariance. |
| Tiny raised fractions, currency, unequal glyph sizes | Historical price literal exact:Base148, Tiny118, Fast Tiny112 of206. Fixed resizing and decoding both may contribute; no causal decomposition is established here. | Historical literal exact:WATE R2048 153/206; Florence 148/206. These do not establish universal equivalence. |
| Extra text / clutter / selecting one requested amount | Full-data crop recognition does not demonstrate selective field reading. No supported PARSeq 50-example selective-reading qualification. | User-observed useful Florence adaptation from roughly50 examples is qualitative evidence here, **not a matched measured90% guarantee**. |
| Arbitrary source image resolution | Any supported RGB source can be resized to the configured H×W. This is not preservation of arbitrary-resolution detail. Train/export buckets and positional embeddings must agree; the engine uses fixed H×W. | WATE has a configurable aspect-aware patch budget; each new budget still needs accuracy, memory and latency checks. |
| Batch throughput / memory | Dynamic-batch ONNX and target-specific TRT profiles are provided. Fast Tiny B1 timings:0.686ms RGB plates /0.889ms prices,682/688MiB. These do not establish B32 latency or the memory of another checkpoint. | Different tasks/cohorts/profile allocations make CCT, WATE and Florence resource comparisons contextual. Weight count is not NVML process memory. |
| Long text / Unicode | The pinned official vocabulary is94 printable non-space characters plus special tokens; max configured label capacity is validated. Unsupported characters or oversized labels raise errors. Historical task checkpoints may add SPACE rows, so their mappings/counts are separate from the default upstream configuration. This is not universal Unicode OCR. | WATE's character vocabulary is also restricted. Florence uses BPE; vocabulary representability is not recognition accuracy. |

Rotation figures use preserved historical checkpoints/runtime outputs, rescored on the same788 crops with unchanged labels; angle names follow those saved records. They must not be combined with current timing or interpreted as a matched latest-engine comparison. No orientation oracle, automatic best-angle selection or extra price correction is implied.

The model family and parameter counts differ from CCT-S and WATERec. Base/Tiny are standard PARSeq options; Fast Tiny is a custom PARSeq training/decode recipe. WATE R and RS share one approximately26.12M architecture with different pretraining, not size tiers. See [experiments](experiments.md) for exact benchmark boundaries, host-RAM scope, negative findings and checked versus inherited workflow status.

All OCR supervision in these workflows is images plus expected text. Bounding-box annotations are not required. No detector, region annotations or private benchmark files are bundled. Keep train/holdout selection separate from final evaluation and never choose a checkpoint from a new scenario report.
